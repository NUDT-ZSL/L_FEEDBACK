# 设计与实现说明

## 1. 单一确定性数据源

场景生成器使用固定种子的 xorshift 序列，生成 5000 个带尺寸、旋转、材质和少量轨道运动的立方体建筑。中心保留角色展示广场。生成结果先写到 `uid166_scene.json`，再通过正式 JSON 加载路径读回渲染器，避免“生成器与加载器是两套数据”的问题。

角色生成器构造 10 根骨骼的拓扑有序层级、10 条动画轨各 49 个关键帧、4 权重蒙皮网格，并写入 `uid166_character.skan`。二进制头包含：

- 8 字节 magic、版本、头长度；
- payload 大小与 FNV-1a 64 位校验；
- 骨骼、顶点、索引、track 和关键帧数量；
- 读入时对 magic、长度、校验、索引范围、权重归一化、父骨骼顺序、时间单调性做完整验证。

浮点写盘统一量化到 `1e-6`，因此 GNU libm 与 Windows CRT 的末位差异不会泄漏到二进制文件。

## 2. BVH

`Bvh` 对世界空间 AABB 的质心做最长轴中位划分，每叶最多 8 个物体。叶子对每个物体再做一次 AABB/视锥相交测试，避免只测试叶子包围盒产生假阳性。

动态物体更新流程：

1. 修改场景物体位置并重算世界 AABB；
2. `updateObject(id, bounds)` 更新叶内 AABB 副本；
3. 从叶子沿父链重算节点并集；
4. 下一次视锥查询立即使用新结构。

查询结果按对象 ID 排序，保证输出集合可比较。

## 3. 视锥与遮挡剔除

帧内先通过 BVH 得到 `frustumVisible`。随后：

- 无窗口基准维护 160x90 上一帧深度缓冲与最大深度金字塔，并把物体投影到上一帧视图；
- 硬件路径使用真实 `D3D11_QUERY_OCCLUSION_PREDICATE`，查询结果只在下一次 `GetData` 时读取，形成至少一帧延迟；
- 正常相机变化时融合视锥结果、上一帧深度层次和硬件查询状态；
- 相机移动超过 `1.25 m` 或每帧转动超过 `0.5°` 时进入快速路径，仅使用上一帧深度层次的保守测试；屏幕矩形按相机位移扩张，越界时拒绝剔除；
- 运动物体不使用跨帧硬件遮挡状态。

基准的深度层次由物体真实投影矩形确定性构造，目的是验证延迟、集合分区和策略一致性；实时模式使用实际场景几何做遮挡预深度和查询。

## 4. 级联阴影

`computeCascades` 使用 practical split（lambda=0.75）计算三级分割。每级：

1. 取当前级视锥 8 角点；
2. 计算包围球中心和半径；
3. 用固定 `stabilizationSize=2048` 计算 texel；
4. 在光源空间把中心 X/Y 吸附到 texel 网格；
5. 生成正交投影并输出来源视图投影矩阵。

稳定化尺寸与动态阴影纹理尺寸解耦，所以阴影质量变化只触发重新绘制，不会改变矩阵。固定相机、固定方向光和固定稳定化尺寸下，矩阵在每个浮点元素上完全一致。

## 5. 局部光源阴影策略

场景固定为 1 个方向光 + 2 个点光源 + 2 个聚光灯。点光源写入 `TextureCubeArray`（每个光源 6 个 DSV 面），聚光灯写入 4 层 `Texture2DArray`。

每帧对每个局部光源计算：

- 光源影响体是否与相机视锥相交；
- 是否有最终可见物体落入影响体；
- 变换是否变化、角色动画是否影响该光源、阴影分辨率是否变化、是否首次创建。

候选按动画脏标记和上次更新时间排序，每帧最多更新 2 个灯。未获预算的灯输出 `deferredBudget` 来源位；每个灯始终输出矩阵，即使本帧跳过更新。

## 6. 命令记录与合并

`CommandRecorder` 在 Windows 下使用 `CreateThreadpoolWork`/`SubmitThreadpoolWork`/`WaitForThreadpoolWorkCallbacks`；其他平台使用等价的标准线程实现。

- worker 原子领取 16 条命令块；
- 命令按可见 ID 的固定位置写入，不依赖线程完成顺序；
- 每个 worker 记录命令数和耗时；
- 超过配置预算时停止领取，主线程串行补齐缺失命令，保证正确性优先，并输出 `budgetHit`/`budgetExceeded`；
- 主线程按材质合并为最多 8 个静态实例批次，降低实际 draw call。

## 7. D3D11 实时管线

每帧主要阶段：

1. 更新运动物体、BVH、动画 palette；
2. 轮询上一帧硬件遮挡查询和 GPU 时间戳；
3. 更新质量状态；
4. BVH 视锥查询与遮挡融合；
5. 更新 CSM/局部阴影决策；
6. 线程池记录并合并静态渲染命令；
7. 渲染 CSM 3 个切片；
8. 渲染已更新的点光源 6 面、聚光灯 1 面；
9. 主场景：静态实例批次 + 蒙皮角色；
10. 低分辨率场景纹理上采样到交换链；
11. 提交下一轮遮挡查询；
12. Present。

蒙皮顶点着色器最多支持 64 根骨骼，每顶点 4 个骨骼权重。像素着色器循环 4 个局部光源，叠加方向光 CSM，所有光源都采样对应阴影图。

## 8. 自适应质量

控制器使用指数平滑 GPU 帧时间：

- 高于 18.2 ms 连续 5 帧：降低一级；
- 低于 13.6 ms 连续 12 帧：提升一级；
- 每次切换后冷却 8 帧；
- 分辨率比例从 1.0 依次降到 0.5，阴影比例从 1.0 依次降到 0.42；
- 始终保留最近 120 帧记录，负载降低后最终回到默认 1.0。

实时模式使用 timestamp disjoint/frequency 计算 GPU 毫秒数；基准使用包含可见物体、阴影更新数和当前质量系数的确定性模型，并加入第 20–45 帧的固定负载尖峰以覆盖升/降级路径。
