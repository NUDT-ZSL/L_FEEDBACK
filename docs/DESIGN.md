# 设计说明

## 模块边界

- `model.*`：内置 ASCII 样本生成、解析、骨骼拓扑校验、权重归一化、姿态采样。
- `skinning.*`：绑定逆矩阵、LBS 位置/法线、变形面法线、退化计数。
- `mesh_io.*`：版本化小端网格二进制、PPM 编码与头校验。
- `render.*`：固定正交相机、方向光、逐三角形 Z 缓冲光栅器。
- `sha256.*`：自包含 SHA-256。
- `snapshot.*`：清单、原子文件替换、帧校验、隔离区。
- `pipeline.*`：启动状态机、线程池、确定性提交、摘要、错误码。

所有运行时模型都来自 `generateAsciiSample()`。生成器先构造骨骼和网格，再序列化
成严格 ASCII，随后由 `parseAsciiModel()` 重新读取。姿态、蒙皮和渲染不使用内存中
直接构造的旁路模型，而是实际 ASCII 输入。

## ASCII 输入语法

```text
ASCII_MODEL 1
sample <name>
duration <seconds>
bone_count <N>
bone <i> <name> <parent> <tx> <ty> <tz> <qw> <qx> <qy> <qz>
... N 条骨骼记录 ...
keys <i> <K>
key <time> <tx> <ty> <tz> <qw> <qx> <qy> <qz>
... 每根骨骼 K 条关键帧 ...
vertex_count <V>
vertex <i> <x> <y> <z> <W> <bone> <weight> ...
... V 条顶点记录 ...
triangle_count <T>
triangle <i> <a> <b> <c>
... T 条三角形记录 ...
end
```

校验包括：

- 恰好一个根骨骼，父索引有效，所有骨骼由根可达，无环。
- 每根骨骼关键帧时间严格递增且非负；四元数归一化。
- 顶点权重骨骼索引有效、值非负；同骨骼权重合并后归一化。
- 三角形索引有效；退化三角形允许存在但计入统计。

DFS 先序存于 `evalOrder`。输入中的骨骼数组顺序不必等于求值顺序；实际传播严格
按 `evalOrder`，因此父骨骼总在子骨骼之前完成。

## 时间采样

输出帧时间：

```text
t(i) = duration * i / (frameCount - 1),  frameCount > 1
t(0) = 0,                               frameCount = 1
```

关键帧插值不依赖 `t(i)` 的帧率。对时间 `t` 查找相邻关键帧 `[a,b]`：

```text
u = (t - a.time) / (b.time - a.time)
translation = lerp(a.translation, b.translation, u)
rotation = slerp_shortest(a.rotation, b.rotation, u)
```

时间在首/尾关键帧外时分别钳制。四元数点积为负时先取反，保证最短路径。

## 线性混合蒙皮

绑定全局矩阵在加载时计算一次。每帧：

```text
skin_b = pose_global_b * inverse(bind_global_b)
p' = sum_b normalized_weight(v,b) * skin_b * p
n' = normalize(sum_b normalized_weight(v,b) * linear3(skin_b) * n)
```

由于每个骨骼变换只有旋转和平移，`linear3(skin_b)` 对法线是刚性旋转。若权重和
为零，顶点直接保持绑定 `p` 和 `n`，并写入 `zero_weight_report.txt`。所有蒙皮
计算使用 `double`，最终网格坐标和法线以 IEEE-754 `float32` 小端序列化。

变形面法线：

```text
face_normal = normalize(cross(p1 - p0, p2 - p0))
```

因此面法线与输出索引顺序一致。长度平方小于等于 `1e-24` 的三角形不归一化，
写零法线并递增退化计数。

## 光栅器

相机位置由绑定包围盒中心和一个固定观察方向推导，投影范围由绑定顶点在相机基
上的投影包围盒加 12% 边距确定。之后所有帧复用同一相机，不随时间重新取景。

每个三角形：

1. 用变形面法线与固定相机 `forward` 做背面剔除。
2. 投影到屏幕，按像素中心 `(x+0.5, y+0.5)` 计算重心坐标。
3. 用线性深度做严格小于测试；等深时低三角形索引先写入并保留。
4. 用固定方向光 `normalize(-0.42, 0.82, 0.63)` 做 Lambert 着色，固定环境光。

每个输出帧拥有独立 Z 缓冲，不存在跨线程共享像素或浮点累加。背景也由宽高和
像素坐标的函数生成，不含时间戳或随机数。

## 并行与确定性合并

任务队列是待计算帧号数组。工作线程通过 `atomic.fetch_add` 领取唯一任务；
实际创建线程数取 `min(requestedThreads, tasks.size())`。帧计算、文件写入和清单
提交彼此独立，互斥锁只保护内存清单与清单文件写回。

工作线程可以乱序完成，但：

- 每个帧文件内容只由输入、配置、帧号决定。
- 清单序列化前按帧号排序。
- 最终摘要只记录帧计数和错误码，不记录线程数、耗时或调度顺序。
- 线程数不进入输入哈希。

因此相同输入下串行和任意并行度的文件树逐字节一致。

## 快照状态机

启动顺序：

1. 生成并解析 ASCII 模型，计算包含模型文本和管线配置的输入哈希。
2. 读取 `manifest.txt`。
3. 版本未知：写 `E1003`、独立报告、隔离旧产物、全量重建。
4. 清单损坏或缺失但有产物：写 `E1001/E1002`、隔离、全量重建。
5. 输入哈希或帧数变化：写 `E1004`、隔离、全量重建。
6. 否则逐帧按 `0..N-1` 校验。首个缺失或损坏帧记为恢复起点，复用更早的有效帧，
   重算起点及之后所有帧。

清单在启动后立即以 `complete=0` 写入，然后每提交一帧重新原子写入。全部帧完成后
才写 `complete=1`。因此 SIGKILL 只可能造成：

- 清单之前提交过的帧均可复用。
- 未入清单的帧文件是孤儿，下次会重算。
- 临时文件在下次启动时由 `.tmp` 清理。

## 原子写与隔离

`writeFileAtomic` 写同目录唯一临时文件，关闭并检查流状态后替换目标。Windows 若
替换失败，删除目标并再次改名。清单和每个帧文件分别原子；二者之间不是事务：
若在两者之间被杀，旧清单校验和会识别出不一致，于是触发恢复。

全量重建前，旧快照顶层条目（清单、`frames/`、输入、摘要等）整体移入
`quarantine/<reason>/`。`errors/` 与隔离区自身不被移动，因此独立错误报告在重建
后仍保留。隔离目录名冲突时追加递增编号。

## 摘要与退出

`summary.txt` 包含状态、成功帧数、复用帧数、本次重算帧数、零权重顶点数及去重
排序后的错误码。正常结束、业务恢复完成和捕获到的 SIGINT/SIGTERM 都会写摘要。
SIGKILL 不可捕获，不写摘要，但已有清单足以恢复。
