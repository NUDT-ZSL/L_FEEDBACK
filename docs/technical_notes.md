# 技术说明与验证记录

## 1. 总体架构

导出流水线为纯函数式的分阶段处理，所有阶段只依赖 Python 标准库：

1. `parser.parse_project` 校验 JSON 并构造内存模型，同时计算规范化工程哈希。
2. `timeline.build_timeline` 用每说话人状态机把事件转成采样级片段与 PTT 脉冲。
3. `synthesis` 按需确定性生成源波形、抗混叠变调、PTT 杂音与首尾提示音。
4. `renderer.RenderEngine` 以固定块为单位累加各频道声音、应用增益与软限幅。
5. `exporter.export_project` 持久化分片与原子快照，最终拼接 WAV 并写清单。

校验阶段在任何输出目录创建之前完成，因此解析失败不会留下输出文件或临时文件。

## 2. 确定性与逐字节一致

- 随机源使用固定 32 位 LCG（模数 2147483647），不依赖 `random` 模块的全局状态。
- 波形以双精度相位累加生成正弦基频、一次谐波、慢速颤音与微抖动，再存入
  `array('f')` 单精度浮点，IEEE-754 运算在支持平台上结果一致。
- 规范化哈希来自 `json.dumps(sort_keys=True, separators=(',',':'))` 的
  SHA-256，作为续渲时识别工程内容是否变化的唯一依据。
- 16-bit PCM 采用小端 `struct.pack('<h')`，字节序显式固定，与主机字节序无关。

## 3. 变调与抗混叠

变调系数为 `ratio = 2 ** (semitones / 12)`。上半音时先经两级串联 RBJ biquad
低通（截止频率 `min(0.9 * Nyquist, Nyquist / ratio)`），再以线性插值按
`source_position = index * ratio` 重采样。变调前后缓冲区采样数相同，因此
事件在时间轴上的绝对起点与时长不变；超出源素材长度的位置填零。渲染器在片段
内通过取模循环复用源波形，循环边界发生在渲染层而非变调层，避免回绕跳变。

## 4. 时间轴语义

- tick 到采样采用毫秒精度的整数映射 `(tick * sample_rate) // tick_rate`。
- 同 tick 事件按其在数组中的顺序处理，`switch`、`block`、`unblock` 会先闭合
  当前片段再以新状态开启连续片段，因此说话时长不丢失。
- 屏蔽与静音不删除片段：屏蔽片段仍保留在时间轴上并标记 `blocked`，渲染为静音；
  频道 `muted` 同样输出静音，清单中的 `muted_channels` 可验证该效果。
- 未闭合 `start`、无匹配 `end`、负长度、零长度等异常统一进入错误清单并以
  退出码 2 结束，不做静默丢弃。

## 5. 混音、增益与软限幅

- 频道增益以 `10 ** (gain_db / 20)` 转换为线性系数，只作用于所属片段。
- 立体声使用等功率声像（余弦/正弦），单声道直接叠加。
- 软限幅为 `math.tanh`，对 `|x| <= 1` 保持原值，超过 1 平滑压缩到渐近 ±1。
- 清单分别报告混音前单源峰值、软限幅前总线峰值、软限幅后峰值，以及
  `clipped_samples` 与 `clipped_frames`（任一声道超 1 即计为削波帧）。

## 6. 提示音与时长延长

提示音为固定种子的双音音型，带边缘淡入淡出。开场提示音从 0 开始叠加；结束
提示音从最后一条有效语音（含 PTT）末尾开始，因此不覆盖语音。若自然时长不足，
总时长延长到 `last_voice_end + outro_length`，清单的 `outro_extension` 同时
给出采样数与毫秒数。

## 7. 分片、快照与中断恢复

- 每个分片先写到同目录临时文件，`flush + fsync` 后 `os.replace` 原子改名，
  快照同样以「临时文件 + 原子替换」写入，杜绝部分写。
- 快照包含引擎版本、工程哈希、采样率、声道数、已完成采样数、总分片紧凑清单
  与累计混音统计。
- 续渲先校验哈希、引擎版本、采样率与声道布局，再逐个核对分片字节数；任何一项
  不匹配即清空旧分片与快照，从零重导，并在清单 `resume.rejected` 中说明。
- 已持久化前缀之后、跨越恢复边界的片段会通过 `seek_to_sample` 定位，重叠部分
  按采样区间裁剪，保证恢复后与一次性导出逐字节一致。
- 可处理信号（SIGINT/SIGTERM）仅置位标志，引擎完成当前分片、落盘快照后以
  退出码 10 退出；强制终止时无退出报告，重启仅凭磁盘上的分片与快照恢复。

## 8. WAV 封装与清单

使用标准库 `wave` 顺序写入 RIFF 头、fmt 块与 data 块，16-bit PCM 天然偶数对齐。
清单字段覆盖采样率、声道数、总采样数、频道增益、三类峰值、削波数、尾音延长、
分片数与错误清单；中断时清单 `status` 为 `interrupted` 且 `errors` 非空。

## 9. 实测验证结果

以下结果在工作区本地以解释器直接运行得到（本机 Python 3.14，代码仅使用
3.11 兼容的标准库语法）：

- `python main.py --selftest`：27 个用例全部通过，覆盖解析错误码、引用错误、
  tick 乱序、时间轴边界、确定性合成、变调长度/频率、抗混叠衰减、削波统计、
  静音/屏蔽、提示音延长、快照字段、哈希不一致拒绝续渲、2 万事件大规模工程。
- `python main.py --demo out`：立体声、削波、单声道三个工程均以退出码 0 完成，
  样本工程产生 12 个分片，清单 `status=complete`、`errors=[]`。
- 中断续渲：模拟两个分片后中断，首次退出码 10、无 WAV 残留；再次运行退出码 0，
  恢复 WAV 与一次性导出 `sha256` 相同、字节完全相等。
- 真实 SIGINT：子进程运行中发送信号，退出码 10，快照存在且 WAV 缺席；续渲
  退出码 0；随后修改工程 tick，旧快照被拒绝并从零重导，清单 `resume.rejected=true`。
- 校验失败：错误采样率、tick 乱序、未知频道引用均以退出码 2 输出含 `path`/
  `event_index` 的结构化错误，输出目录无 WAV、分片或临时文件残留。
- 大规模：8 名说话人、20000 个事件（2 万片段 + 4000 PTT）在约 15–17 秒内完成，
  断言分片数、片段数、清单完整性与 WAV 落盘。

## 10. 已知边界

- 渲染为纯 Python 逐采样实现，长赛事的吞吐受解释器速度限制；设计上以分块和
  游标保证内存与可恢复性，未引入第三方数值库。
- 若同一说话人出现嵌套 `start`，前一片段在该 tick 强制闭合并记录 `E_EVENT`，
  不会产生无限区间。
