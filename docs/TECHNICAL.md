# 技术说明

## 1. WAV I/O

`audiorepair/wavio.py` 使用 RIFF 分块解析而不是依赖第三方音频库：

- 只接受 `WAVE_FORMAT_PCM`；
- 位深必须为 16 bit；
- 采样率必须为 44.1 kHz 或 48 kHz；
- 声道数必须为 1 或 2；
- 校验 `block_align` 和 data 分块对齐；
- 其它格式统一抛出 `AUDIO_UNSUPPORTED_FORMAT`。

写入使用规范 44 字节 WAVE 头，16-bit little-endian，采样值采用
`clip(x, -1, 32767/32768) * 32768` 后确定性取整。输出采样率和声道数继承输入。

## 2. BS.1770 响度

`audiorepair/loudness.py` 实现：

- 44.1 kHz 和 48 kHz 的 K 加权预滤波 + RLB 高通系数；
- 400 ms 分析块、100 ms 步进、75% 重叠；
- `-70 LKFS` 绝对门限；
- 相对门限 `-10 LU`；
- 单声道/立体声声道权重均为 1.0。

级联双二阶滤波器转换为固定长度冲激响应，并通过 FFT 线性卷积实现。滤波器系数
和卷积顺序固定，因此相同输入和采样率得到稳定结果。短于 400 ms 的片段使用其
可用样本作为一个测量块，以便局部规范化。

## 3. 分段与增益

时间轴先换算成整数采样点。所有片段必须无间隙、无重叠并覆盖整条输入。每段：

1. 从原音频截取 `[start_sample, end_sample)`；
2. 测量原始积分响度；
3. 执行 WSOLA；
4. 测量伸缩后片段响度；
5. 应用 `target_lufs - measured_lufs` 的分段增益。

拼接后，再按整轨积分响度执行最多 8 次闭环校正：

- 每次测量误差并施加增益；
- 若样本峰值超过内部安全上限，使用 `tanh` 平滑压峰；
- 若最终仍无法在峰限下进入响度容差，抛出 `LOUDNESS_UNREACHABLE`。

最终逐声道减去均值。量化后重新解析输出，重新测量响度、峰值和直流，任何约束
不满足都不会提交文件。

## 4. 锚点保持 WSOLA

`audiorepair/wsola.py` 把片段按

```text
source:   0, s1, s2, ..., N
target:   0, t1, t2, ..., M
```

拆成若干区间。每个源区间都有明确目标长度
`ti+1 - ti`。目标采样点因此不会因整段均匀拉伸而累积漂移。

区间内合成参数固定为：

- 帧长约 24 ms；
- 合成帧移为帧长一半；
- 分析位置在名义映射点附近搜索；
- 搜索半径约 4 ms；
- 相似度量使用前帧尾部与本帧头部的归一化互相关；
- 使用半周期偏移 Hann 窗重叠相加并逐样本归一化窗和。

这种实现保留了 WSOLA 的波形相似性搜索和重叠相加特性，同时把音节边界作为硬
锚点。报告中的 `span_stretch_ratios` 是各区间实际目标/源长度比；所有比值在
加载时间轴时即校验是否位于 `stretch_range`。

## 5. 线性交叉淡化

相邻片段以时间轴指定的采样数 `d` 重叠：

```text
t = [0, 1] 的线性斜坡
out_tail = previous_tail * (1 - t) + next_head * t
```

权重严格满足 `(1-t) + t = 1`，不会引入等功率交叉淡化常见的 `+3 dB` 中心抬升。
报告记录最终输出中的交叉淡化采样起止点和曲线类型。

## 6. 边界测量与报告一致性

输出量化后，边界检测器在预期位置附近搜索：

1. 局部短时能量达到谷值且显著低于邻域时，取低能量间隙中心；
2. 否则取局部正向谱通量最大值。

报告保留检测方法、目标/实际采样点和毫秒误差。若最大误差超过 20 ms，整次任务
以 `BOUNDARY_MISALIGNED` 失败，不提交输出。

最终响度、峰值、直流、实际边界和输出哈希均在完成 16-bit 量化后重新测量或计算。
因此报告与外部重新读取 WAV 的结果一致，而不是描述尚未量化的内部缓冲。

## 7. 确定性与并发

- 不使用系统时间、随机数或外部服务；
- JSON 使用固定键排序、固定缩进和固定浮点舍入；
- WAV 使用固定头布局和固定量化；
- 每个任务拥有独立的 NumPy 缓冲区；
- K 加权冲激响应缓存只在首次构造时受锁保护，构造结果固定；
- 线程池按任务独立处理，结果在汇总时按清单顺序重排；
- 正常和异常路径都调用 `shutdown(wait=True)`，异常时额外取消未启动任务。

因此 `jobs=1` 和多线程执行产生相同的每个任务 WAV 与报告字节。

## 8. 提交协议

成功处理完成后：

1. 在 WAV 目录原子创建 `<output>.incomplete`；
2. 写 WAV 临时文件并 `fsync`；
3. 写报告临时文件并 `fsync`；
4. 原子替换 WAV；
5. 原子替换报告；
6. 删除完整性标记。

任一步骤失败时清理临时文件和本次已提交文件；若清理本身失败，完整性标记仍保留，
不会把半成品误报为完整输出。
