# Technical Notes

## 1. 确定性高度场

`Terrain` 固定生成 `512×512` 个顶点，世界范围是 `[0, 511]²`。每个顶点使用整数哈希
驱动的 value noise，再叠加用户指定层数的 fBm。哈希只使用整数运算和 IEEE-754
浮点运算，不依赖时间、线程调度或外部资源。

频率与振幅直接来自命令行。最终高度为

```text
height = amplitude * sum(weight_i * noise(frequency * 2^i * p)) / sum(weight_i)
```

其中 `weight_i = 0.5^i`。高度场生成一次并计算 FNV-1a 校验和；校验和与参数共同构成
地形版本号。

合法范围：

- `seed`: `uint32`
- `amplitude`: `(0, 4096]`
- `frequency`: `(0, 64]`
- `octaves`: `[1, 12]`

## 2. 四叉树和屏幕空间误差

每个叶节点渲染固定的 `16×16` 四边形补丁（`17×17` 顶点）。四叉树深度为 0..5：

```text
global resolution = patchQuads * 2^maxDepth = 16 * 32 = 512
```

因此最大深度与 512 高度场分辨率一致。高度纹理由 `Terrain::sampleHeight` 双线性采样，
并对采样坐标做边界钳制，最高深度不会产生索引越界。

每个节点的 AABB 由 x/z 范围和该矩形内高度采样极值得到。选择过程：

1. 用当前帧 view-projection 提取六个裁剪平面。
2. AABB 完全位于任一平面外侧时停止并裁剪该节点。
3. 否则估算屏幕空间误差：

```text
cellSize       = nodeSpan / 16
geometricError = cellSize * (1 + heightRange / 2)
sse            = geometricError * viewportHeight /
                 (2 * tan(fovY / 2) * distanceToAabb)
```

4. `sse` 超过阈值且未到最大深度时细分为四个子节点，否则作为叶节点渲染。

选择器使用上一帧缓存状态做滞回：上帧为叶节点时提高细分阈值，上帧为内部节点时降低
合并阈值；同一节点的状态变化后至少驻留 4 帧。每帧仍会重新计算视锥和全部候选节点，
固定回放因此逐帧确定。

## 3. 接缝检测与顶点位置缝合

渲染叶节点在 `maxDepth` 对应的 `32×32` 单元网格上登记 owner。对每个叶节点的四条边，
沿边界单元查询相邻 owner，得到公共边的重叠区间和邻节点深度。

只有“当前节点更精细、邻节点更粗糙”的区间进入缝合：

- CPU 端 `StitchSegment` 记录边界参数 `[t0, t1]`、低精度邻节点原点和跨度。
- 低精度边被看作由它自己的 17 个边界顶点连接而成的折线。
- 高精度侧每个边界顶点沿该折线做线性插值，得到目标高度。
- 仅改变高精度侧顶点的 y 位置；x/z 仍落在低精度边上，两侧几何位置重合。

同一套 `StitchSegment` 数据同时用于：

1. GPU 顶点着色器的边界位置钳制。
2. CPU 缓存中的边界顶点偏移。
3. 接缝高亮线段生成。

高亮只生成存在深度差异的边界区间，不会给整片地形着色。测试逐段重算低精度边插值与
最终高精度边高度，当前固定回放的 `maxStitchResidual = 0`。

## 4. 索引批次和 GPU 数据

GPU 地形渲染使用：

- 一个 `512×512 GL_R32F` 高度纹理，只在初始化时上传一次。
- 一个固定的 `16×16` 补丁索引缓冲，共 1536 个索引，只上传一次。
- 一个动态节点元数据 SSBO，每帧更新可见节点映射和低精度邻边描述。

每个 LOD 深度对应一次 `glDrawElementsInstanced`。实例不是重复上传顶点或索引，而是在
顶点着色器中根据实例元数据计算世界坐标、双线性高度和缝合高度。因此绘制调用数量最多
为 `maxDepth + 1 = 6`，而不是与节点数量成正比。

节点元数据每项 1056 字节，包含：

- 世界原点、跨度、深度；
- 高度 AABB；
- 4 条边、每条最多 8 个低精度重叠区间。

接缝高亮使用一个独立的小型动态线段缓冲，只上传实际差异段。

## 5. 节点缓存

`NodeStateCache` 以节点编码为 key，记录：

- 地形版本号；
- LOD 选择结果与叶/内部状态；
- 最近使用帧；
- 边界顶点偏移列表。

版本不匹配时立即清除旧偏移并重新计算，禁止沿用旧地形参数的结果。节点移出视锥后记录
保留；重新进入且版本一致时命中缓存。缓存有容量上限，超过时只回收未在本帧访问的
最少最近使用项。测试覆盖了命中、版本失效和容量回收。

## 6. 确定性回放

固定回放中：

```text
frameTime = frameIndex * timeStep
```

相机位置线性插值，yaw 走最短角路径，pitch 线性插值。每帧输出一行 JSON，包含：

`triangles`、`drawCalls`、`stitchVertices`、`seamSegments`、各 LOD 叶节点数、裁剪数、
缓存命中/失效、最大缝合残差和高度校验和。

数值格式使用 `std::locale::classic()` 和固定精度，避免系统区域设置改变输出。

## 7. 架构

- `terrain_core`: 无窗口、无 OpenGL 的地形/四叉树/接缝/缓存/软件光栅化核心。
- `terrain_lod`: 命令行与 GLFW 桌面程序。
- `src/gl`: 自包含 OpenGL 4.6 函数加载器、离屏 FBO 渲染器。
- `tests`: 确定性、裁剪、LOD、缝合残差、缓存版本、路径解析、PPM 输出测试。

软件后端与 GL 后端共用同一份叶节点选择、缝合偏移和接缝段数据，因此无显示器环境中的
截图和统计仍能验证算法结果。GL 后端已完成 GLFW 3.4/GLM 1.0.1 链接验证；当前 WSL
环境没有可用的 OpenGL 4.6 EGL/GLX 配置，记录见
`artifacts/validation/gl_validation.txt`。Windows 4.6 硬件上使用 `--backend gl`
可执行真实 FBO 截图路径。
