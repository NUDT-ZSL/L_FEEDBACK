# 技术设计说明

## 1. 总体数据流

```
确定性信号 -> 损伤模拟(丢包/乱序/抖动) -> stream_*.pkt + ground_truth
                                                  |
包解析(校验/错误码) -> 每路抖动缓冲 -> 欠载? PLC : 真实帧
                                                  |
                         全局帧索引对齐 -> 多路混音 -> WAV + JSONL
```

整条管线运行在**单线程虚拟时钟事件循环**中（`engine.py`）。事件只有两类：
包到达（按模拟到达时刻）与 20ms 播放 tick。事件放入最小堆，按
`(时间, 类型优先级, 序号)` 排序；同一时刻先处理到达再处理 tick，避免无谓
欠载。循环在“下一事件时刻”推进，没有 sleep 轮询，因此是非忙等待的。

## 2. 帧重组与抖动缓冲

- 时间戳（uint32）整除每帧样本数 960 得到全局帧索引，天然处理乱序。
- `JitterBuffer` 以帧索引为键保存 float32 帧；目标深度可配 2–10，且配置
  深度同时作为硬容量上限。
- 自适应：发生欠载时目标深度 +1（上限 10），连续 25 个干净帧后回落，
  始终不超过配置的硬容量。
- 容量已满时新包到达触发**背压**：记录 `buffer_overflow` 与
  `backpressure`，丢弃最旧的非关键音频帧（语音可由 PLC 重建），接收路径
  立即返回不阻塞。
- 已播放帧的迟到包标记 `late_frame_dropped`；重复包标记 `backpressure`。
- 内存预算：缓冲帧 + PLC 历史按 float32 字节数计入，深度 10 时约
  `(10 + 4) × 960 × 4 ≈ 54KB`，远低于 256KB 上限；超预算会抛 `MemoryError`。

## 3. 丢包补偿（PLC）

每路独立 `PlcState`，保留最近 4 帧历史：

1. **基音周期重复**：在 60–600 样本（800–80Hz）滞后范围内用归一化自相关
   估计基音周期，置信度 ≥ 0.45 时采用。补偿帧以历史末样本同相位的周期
   延续构造，并与历史尾段做 240 样本等功率交叉淡化，保证拼接处无点击。
2. **线性预测回退**：基音不可靠（噪声/清音）时，在近期历史上解二阶 LPC
   正规方程，逐样本外推。
3. 连续补偿最多 3 帧，且每帧按 `0.85^(n-1)` 衰减，避免能量发散。
4. 第 4 个及以后的连续丢失输出**静音**（`method=silence`，`plc=false`），
   置位长丢失状态；真实帧回归时做淡入并标记 `plc_recovery` 恢复点。

JSONL 中 `plc`、`plc_method`、`plc_run_length`、`recovery` 使每个补偿帧
都可被日志追踪。

## 4. 多路混音

按全局帧索引把 2–4 路对齐后逐帧混音：

- 用 RMS 阈值判定每路活动状态，近静音路不占余量（headroom）。
- 等功率模式：活动路增益 `1/sqrt(N)`；线性模式：统一 `1/N`。
- 求和后硬限幅到 [-1,1] 再量化 int16，杜绝溢出；记录 `mix_peak`、各路
  `gains` 与 `active`。

## 5. 确定性损伤模拟

`simulator.py` 为每路使用派生种子 `seed + stream_id*1009` 的独立
`random.Random`，损伤包括：

- 独立伯努利丢包 + 可选每 40 帧一次的 4 帧突发丢包；
- 相邻存活包按概率交换，模拟乱序；
- 到达抖动支持正态（截断到非负/上限）或均匀分布；
- 可选追加非法长度与截断记录，覆盖解析器错误分支。

真值 `ground_truth.jsonl` 逐帧逐路记录 `source`、`original_frame_index`、
`sample_offset`、`clean_rms` 与 `lost`，供 `verifier.py` 对齐核验。除种子外
无其他熵源，重跑字节级一致。

## 6. 诊断日志与核验

每行一帧，关键字段：

- `frame_index` / `timestamp` / `time_ms`：严格单调的时间轴。
- `streams.stream_<id>`：序列号覆盖、是否真实帧、PLC 信息、缓冲水位/目标/
  内存字节。
- `gains` / `active` / `mix_peak`：混音增益、活动状态与峰值。
- `events`：本帧所有缓冲/PLC 事件。

`verifier.py` 校验：日志行数=真值帧数、帧索引严格 +1、时间戳正确、每个
真值丢包都被 PLC/静音处理、干净帧缺失必伴随溢出/欠载事件、WAV 时长与
`帧数×20ms` 偏差 ≤5ms。

## 7. 资源与健壮性

- 单线程事件循环，无锁、无忙等待；接收路径 O(1) 入缓冲，背压即丢最旧帧。
- 所有解析异常转成业务错误码写 stderr 并跳过，不中断主流程。
- 配置/IO 异常在 CLI 层捕获，映射为退出码 2/3。
- 仅依赖 numpy 与标准库，WAV 使用 `wave`，跨平台且无需音频设备。
